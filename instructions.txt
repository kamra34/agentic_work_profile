AI Resume Tailoring Platform
Product Overview
• Intelligent CV Customization Automatically analyzes job descriptions using dual AI models
 (OpenAI GPT-4o + Anthropic Claude) to extract requirements, then tailors your master CV profile
  by intelligently selecting and highlighting the most relevant experiences, skills, and achievements for each specific job application. 
• Real-time ATS Optimization Provides instant ATS (Applicant Tracking System) compatibility scores and fit analysis from both AI
   models, with live recalculation as you customize content visibility. Interactive preview lets you hide/show specific bullet points
   , roles, or entire sections while monitoring how changes impact your scores before generating the final PDF. 
• Professional PDF Generation Converts your tailored content into clean, ATS-friendly PDF resumes with proper formatting,
    hierarchical structure (company → role → achievements), and customizable visibility controls. 
    Download production-ready CVs optimized for both automated screening systems and human recruiters.
• Application Tracking Dashboard Manage your entire job search pipeline with status tracking (Draft → Applied → Interview → Offer),
 interview scheduling, company details, salary ranges, and historical ATS scores. Visual dashboard shows application statistics,
  status pipeline, and allows filtering/sorting to stay organized throughout your job hunt.

Analysis of profile_nodes Table Structure
Based on the database query and model inspection, here's the complete understanding:
Table Structure:
The profile_nodes table uses a self-referential hierarchical design with these key columns:
Identity & Relationships:
id: Primary key (integer)
global_id: Unique UUID for tracking nodes across CV tailoring
profile_id: Foreign key to profiles table
parent_id: Self-referential foreign key (NULL for root nodes)
Hierarchy Tracking (Performance Optimization):
level: Integer depth (0=root/section, 1=direct child, 2=grandchild, etc.)
root_id: Foreign key pointing to the top-level section node (level 0)
Content:
node_type: Flexible string ("section", "entry", "bullet", "paragraph", "item", etc.)
title, subtitle, content: Text fields
start_date, end_date, location: Optional metadata
order: Display order within siblings
is_visible: Boolean for show/hide functionality

Key Insights:
Complete Traceability: Every node's position in the hierarchy is absolutely determinable through:
parent_id - immediate parent
level - depth from root
root_id - which top-level section it belongs to
Recursive query through parent_id chain reaches the root
Flexibility: The structure supports any nesting pattern:

Section → Paragraph → Bullet

Performance: The denormalized level and root_id columns eliminate the need for recursive queries in most cases
Data Integrity: SQLAlchemy relationships with cascade="all, delete-orphan" ensure that deleting a parent removes all descendants
